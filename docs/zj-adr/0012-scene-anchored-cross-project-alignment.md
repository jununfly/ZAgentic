# 跨项目对齐单位改为固定场景集（场景锚定）

2026-11-08。产品项目图式横比模型原先试图用「节点语义等价」把多张项目图对齐后再比较；本 ADR 把对齐单位换成由 Human 独立给定的固定场景集，各图仍按自己的语义独立建成，只在 Stage 3 经场景映射发生对齐。判决来自一次 `zj-grill-with-docs` 会话，SSOT 落在 `docs/agreements/product-project-graphical-cross-comparison-model.md`。

## Context

原模型有三个互相咬住的问题：

1. **没有公共坐标系。** Stage 1 强制各项目按自己的语义独立建图、禁止互相引用，因此节点 ID 与命名天然是项目私有的；跨项目唯一可独立观察的东西是可观察的用户场景（起点 / 终点 / 可观察结果），不是节点。
2. **等价裁决挂错触发条件且不可复核。** H4 只管「跨项目同名节点」，而独立建图下同名只是巧合，主要情形「不同名但语义疑似等价」没有触发机制；文档也没有等价判据，第三方 Agent 只能看到「某人裁决等价」，无法复核裁决本身。强制填写的 `acceptance` 字段全程无下游消费。
3. **候选对来源无解。** 若让执行 Agent 枚举等价候选对，它就得先做语义判断，与 fail-closed「Agent 不得自行推断语义等价」直接冲突。

同时，原模型把「耦合团（无向连通分量）规模」写成「0→1 工作量的真实单元」，但 `requires` 是有向非对称依赖：扇形依赖 `A→B, C→B` 下 A 与 C 可独立交付，无向连通分量却把三者绑成一团。

## Decision

1. **对齐锚点 = 固定场景集。** 由 Human 独立给定，不来自任何 `Graph_i`，带版本 pin 与产品域一手材料证据；只描述可观察场景，**不规定任何节点、模块或实现划分**（否则等于用尺子偷偷塞架构，违反「不预先裁决架构」）。
2. **Stage 1 / Stage 2 不变**：各图按自己的语义独立建成，横切路径与约束各自成清单。Stage 3 才做 `S_i → 场景` 映射，映射本身留 Human 裁决记录。
3. **差异条目是唯一结论载体**：一条 = `场景 × 项目 × 供给四态 × 支撑节点集 × 证据 × 映射裁决`。四态复用母模型 `native / adapted / unsupported / unknown`，参照系是场景；`unsupported` 须绑定一手材料中的显式否定陈述，`unknown` 须附最小验证计划。
4. **节点语义等价降级**为「同一场景内按需裁决」，裁决记录必须引用双方 `acceptance`；不再做全局等价映射表。
5. **摘要指标不参与结论**：SCC 规模分布（不可分割性）、最大依赖闭包（单次交付成本）、扇入分布（变更波及面）三者分开算，只作清单摘要，不得用于排序 / 裁决 / 回灌 / 优先级；无向连通分量不进入本模型。
6. **可选场景集仅作盲区检查**：Stage 2 逐项目原样摘录的观察材料，供 Human 核对遗漏与识别「把项目特有场景误当通用」；Agent 对它零语义操作，核对留痕进报告。

## Considered Options

| 方案 | 拒绝理由 |
| --- | --- |
| 维持节点语义等价，H4 扩到「全部候选对」由 Agent 枚举 | 候选对来源无解；等价判据仍主观；与 Stage 1 独立性、fail-closed 双重冲突 |
| 结构化 `acceptance` + 机器生成候选对 | 把自由文本强行结构化再算相似度，等于把 Human 裁决伪装成机械判定，制造假精确 |
| 场景集 = 所有 `Graph_i` 竖切片的并集 | 尺子由被比较对象生成；且场景集 ⊆ `∪S_i`，无法包含「域内应有但所有项目都未覆盖」的场景，横比失去绝对参照、只剩相对差异 |
| 场景集由报告消费者提供 | 与权责契约冲突：消费者只有复核权，图定义与裁决权在方法论 owner |
| Stage 2 收集的可选场景集可作采纳源 | 绕一道人手把归纳伪装成外部给定，上面「并集」的问题原样复活；故限定为盲区检查 |
| 横比输出引入跨图标量（图编辑距离 / Jaccard） | 标量前提是节点已语义对齐；在对齐靠 Human 逐条裁决的前提下，等于把主观裁决包装成客观数字 |
| 报告消费者只要差异清单、不写摘要 | 过于保守，丢失「共享底座 / 不可分割性」的可观察线索；折中为「摘要只展示、不参与结论」 |

## Consequences

- 新增一个 Stage 3 前置输入（固定场景集），其来源、版本 pin 与「只描述场景」边界成为契约的一部分；场景集变更触发重建。
- `unsupported` 与 `unknown` 终于可机械区分，`adapted` 因场景参照而不再把我方适配裁决塞进描述层；母模型四态可直接复用，回灌接口降级为「可选素材，母模型侧接口待定义」。
- `acceptance` 有了下游消费（场景内等价裁决的必填引用），不再是空转字段。
- 代价：Stage 3 前多一次 Human 给定与盲区核对留痕；报告结构由「四维对齐表」重排为「场景 × 项目」的差异条目清单。
- 本文是方法论约定，不含实现体；YAML 形状与复核条件是纸面契约，不代表已有脚本或门禁在运行。
- **范围说明**：非能力范畴（非功能约束 / 数据契约 / 外部依赖 / 参与主体）的处置已由同日

## Amendment (2026-11-08)

同日追加决策：**`F / T` 二分不扩充**。本 Amendment 不改变上文的场景锚定判决。

### Context

原 agreement 把 `V_i` 定义为 `F_i ∪ T_i`，两类都是「可独立陈述与验收的能力单元」。仓库里存在大量既非 F 也非 T 的一手描述：数据不出域与本地索引跨次复用、第三方 API 的许可与用途约束、响应 < 200ms 的合规门槛、长期记忆数据对象、以及场景中承担编辑 / 审批 / 执行的角色。若它们无处安放，两个都 `native` 支撑同一场景的项目会显得结构相同——而产品定位的核心差异恰恰在「一个数据不出域、一个依赖第三方模型服务」。

母模型已给出同构先例：`docs/agreements/open-source-capability-fit-decision-model.md`（`C = Compose(...)` 定义见 L42 / L164）把「接口、语义、数据模型、生命周期、许可和运行方式」当作 `C = Compose(...)` 的兼容性验证项与 `E` 的成本分量，**不是 `O` 能力、也不是独立节点**。仓库也已有 `constraints` 字段、`数据边界`、`Non-goals`、保证边界与风险控制矩阵等旁挂清单惯例。

### Decision

1. `V_i = F_i ∪ T_i` **保持不变**；四类事实作为 `context-entries` 旁挂，不给图记号、不进 `Graph_i` 元组、不进 `S.members`、不进有向依赖图。
2. 四类 `kind`：`constraint`（非功能约束）/ `data-contract`（数据契约）/ `external-dep`（外部依赖）/ `actor`（参与主体）。`scope: domain` 归固定场景集所有、由 Human 给定（仍不规定实现划分）；`scope: project` 归各自 `Graph_i`、Stage 2 收集。
3. 差异条目新增 `context-refs` 与 `context-verdicts`，逐条判 `satisfied / violated / unknown`；这**是第二套枚举，不得与供给四态混用**，且是逐条清单不是标量。
4. 接线：Stage 2-h 登记 `project` 级条目、Stage 3-b 判三态、新增复核条件 CHK-10、报告第 3 节与决策记录补该字段；**摘要指标的分母一律排除上下文条目**（它们不是图元素）。

### Considered Options

| 方案 | 拒绝理由 |
| --- | --- |
| 扩 `V` 为多类型节点 | 原子化判据（可独立验收 / 不共用验收条件）对约束、数据、主体失效；`S.members ⊆ V` 会把合规约束当成场景成员；SCC、依赖闭包与扇入在异构图上语义崩坏（依赖边要不要连一条合规约束？）；与母模型 L55 的分工相反 |
| 塞进 `T` 当子类 | 把「数据不出域」写成「能力」是范畴错误，直接违反「技术栈名或框架名不算技术能力」的精神 |
| 明确 out of scope，全交母模型 | 极简且分工清晰，但横比清单会漏掉最关键的产品定位差异；且母模型处理的是单候选采用，不负责多项目结构对比 |
| 只加自由文本 `notes` | 无法逐条追溯、无法判定满足 / 违反，等于把未决策项伪装成已处理 |

### Consequences

- `V` 定义、ID 命名空间主体、原子化判据、SCC / 依赖闭包 / 扇入的图论语义**零改动**，这是选择旁挂而非扩 `V` 的主要收益。
- 原 `kind: constraint` 与图内记号 `C` 的同名异义已由同日符号改名**消除**：图内约束改记号 `RC`（字段 `relation-constraints`、ID `RC::`），复核条件改 `CHK-01`…`CHK-10`；单字母 `C` 在 agreement 中只用于引用母模型 `C = Compose(...)`。`ZJ-CONTEXT.md` 的 `Flagged ambiguities` 保留改名记录，不再是待消歧项。
- 场景集的外部性未破：`domain` 级条目仍只描述条件、不规定节点 / 模块。
- 代价：SoT 多一个顶层字段、差异条目多两层、复核条件多一条、词表多 4 个词条；`context-verdicts` 的 `unknown` 同样受 fail-closed 约束，须附最小验证计划。
- 该决策同样不含实现体，仍为方法论约定。
