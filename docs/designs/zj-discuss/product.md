# zj-discuss — 产品文档（Product）

> 本文是 `zj-discuss` / `zj-discuss-view` 这组技能的产品定义。它是长期权威页；
> 行为细节见同目录 `design.md`，组件与生命周期见 `architecture.md`。
> 角色语义的唯一真源是技能内 `references/role-matrix.md`。

## 1. 一句话定位

`zj-discuss` 是一套**方法论技能**：把 flat chat 扛不住的复杂问题，分解成一主多子的
文档组，按「一事一议」跑多角色独立讨论，产出**完整、严谨、可操作**的解决方案文档组。

它不是单次问答，而是「分解 → 多角色独立讨论 → 合成 → 沉淀处置」的全生命周期 owner。

## 2. 要解决的痛点

- **chat 太薄**：单一 Human + 单一 AI 的线性对话，遇到复杂问题几乎讲不清方方面面，
  结论容易停在首轮锚定，偏差被静默吞掉。
- **没有留痕**：讨论散落在对话流里，复杂问题的决策依据随会话结束而丢失。
- **缺结构**：没有「谁从什么立场发言、是否独立、是否收敛」的纪律，多视角退化成回声室。

## 3. 目标用户与场景

- **用户画像**：zj —— 资深程序员 + 技术架构师 + 技术部门负责人（最多 700 人），
  兼具浅层产品/业务经验；solo 使用为主，无真实市场/竞品压力。
- **典型触发**：面对一个「一句话说不清、flat chat 讨论三轮还悬着」的复杂问题
  （如技术重写保真 vs 进度、技能体系改进、跨仓库方案选型）。
- **非目标**：单点决策、纯信息查询、已有 ADR/PRD 能覆盖的小改动——这些走
  `zj-steelman` / `zj-grilling` / 直接 chat，不必拉起整套文档组。

## 4. 三轴目标（来自 gstack + 决策模型复盘）

用本仓库自创方法论 `docs/agreements/open-source-capability-fit-decision-model.md`
（开源能力拟合决策模型）框定，并结合 gstack v1.2.0 证据，
把改进收敛为三个轴：

| 轴 | 含义 | 关键证据（gstack） | 达成手段 |
| --- | --- | --- | --- |
| **可用性** | 降低跨会话摩擦、降低角色调用与上手成本 | ACP 程序化派生会话、router+preamble、引导式安装 | 启动包生成器、`--all`、准备阶段角色推荐 |
| **严谨性** | 强化独立性保证、防回声室、证据与质量门 | `/codex` 跨 provider 异构独立性、Completion Status 协议 | 动态议程质量门、承重警告、状态协议 |
| **有用性** | 可度量价值 vs flat chat、接受标准、可复核 | compression 度量、completeness 门、user-sovereignty「呈现而非断言」 | 轻量可重算度量、接受标准、呈现而非断言 |

最终决策分类 = **C（选择性复用）**：gstack 作组件来源，zj-discuss 方法体系为自有主体；
**否决** 运行时编排器 / suite-化（会触发约束 1 → D，且让适配层拥有主体状态）。

## 5. 两阶段生命周期（产品级）

- **阶段 1（求解期）**：`discussions/<slug>/` 文件夹整体保留，作为复杂问题
  「求解之前的过程性质权威依据」+ 完整方案（进行态），**非长期文档**。
- **阶段 2（求解后）**：调用 `zj-docs-ontology` 分类沉淀（可复用内容进 `docs/` 权威页，
  过程噪声按删除候选）→ **Human 确认后删除文件夹**。

这既满足「文档组 = 完整解决方案要保留」（阶段 1），又回到政策的「删除」纪律
（阶段 2，且经 Human 确认，不自动删）。

## 6. 范围边界

- **是**：分解方法论 + 每子文档独立多视角讨论 + 合成 + 末段沉淀交接 + 角色池 +
  固定/动态议程编排。
- **不是**：会话运行时/基座（不建 router/suite）、兄弟技能的重实现（steelman/handoff
  只引用）、自行分类迁移（交 docs-ontology）。

## 7. 成功判据（产品层）

- 同一复杂问题，用 `zj-discuss` 比 flat chat **捕获更多偏离 / 分歧**，收敛轮次可控。
- 生成的文档组可被第三方（另一 Human / Agent）**复核**——每个观点标来源、每步拍板留痕。
- 角色选取贴合问题意涵，不冗余（收敛停规则生效）。
