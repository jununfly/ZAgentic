# 开源能力拟合决策模型（Open-Source Capability-Fit Decision Model）

> ZAgentic 自创方法论（SSOT），用于评估是否将某个外部开源项目（或其部分能力）
> 直接采用 / 扩展采用 / 选择性复用 / 继续搜索，产出可复核的 `R × O` 证据矩阵与
> `A/B/C/D` 分类。

---

适用范围：评估一个或多个开源项目能否满足既定需求，以及决定直接采用、扩展采用、选择性复用或继续搜索。

## 目标

以目标需求与候选项目的单位能力为基础，显式评估能力缺口、组合风险和长期所有权成本。该模型可递归使用：继续搜索得到新候选后，重新拆解、组合和判定，直到满足停止条件。

## 核心模型

设：

- `R`：目标需求集合。每项需求应包含优先级、验收标准，以及是否为关键能力。
- `O₁...Oₙ`：候选开源项目分别提供的能力集合。能力结论必须来自固定版本的代码、文档或可复现实验。
- `C = Compose(select(O₁...Oₙ))`：从候选中选择单位能力并验证可组合性后得到的有效供给集合。
- `G = R - C`：尚未满足的能力缺口。
- `E`：采用方案后由自己长期承担的责任。

`E` 至少包括：

- 缺失能力的实现；
- Adapter、协议和语义转换；
- 组件组合与集成测试；
- 部署、运行和故障恢复；
- 上游升级兼容；
- 安全、权限和数据治理。

不能把候选项目能力做简单并集。只有接口、语义、数据模型、生命周期、许可和运行方式能够兼容，并经过验证的能力，才计入 `C`。

## 两个判定量

```text
有效拟合度 = 功能覆盖 × 语义匹配 × 可组合性

总所有权成本 = 初始开发 + 集成 + 持续维护
              + 上游变化适配 + 运行运维 + 安全与治理
```

任何关键能力缺失，都不能由非关键能力的高覆盖率抵消。评估结果应同时报告有效拟合度和总所有权成本，不能只报告功能清单或初始开发量。

## 决策分类

| 决策 | 名称 | 判定标准 |
| --- | --- | --- |
| A | 直接采用 | 有效拟合度高，关键能力完整，`G` 和 `E` 均可忽略；无需维护自有产品层。 |
| B | 扩展采用 | 缺口小且可控；开源项目仍是主体，自有部分是边界清晰、可替换的适配层。 |
| C | 选择性复用 | 缺口较大但自建责任仍可控；自有架构是主体，只复用有独立价值的组件或能力。 |
| D | 继续搜索 | 关键能力缺失、有效拟合度低、组合成本非线性增长，或 `E` 超出可接受范围。 |

扩展采用进一步区分为：

- `B1`：通过外部 Adapter、插件或 sidecar 扩展，不维护 fork；
- `B2`：通过上游贡献补齐能力，并承担贡献被拒绝或延迟的风险；
- `B3`：维护长期 fork，并持续吸收上游变更。

默认优先顺序为：

```text
A > B1 > B2 > C > B3
```

该顺序不是强制结论。若数据控制、可靠性、演进自主性或差异化价值足以抵消所有权成本，可以选择排序靠后的方案，但必须记录理由。

## 可控 B 的边界

“扩展采用”要求自有部分是可移除的薄层。它可以承担：

- 身份映射；
- 查询适配；
- 状态转换；
- claim、lease 等小型协调语义；
- 来源和可追溯信息适配。

它不应重复建设开源主体已经负责的：

- 存储和同步基础设施；
- 完整检索或记忆流水线；
- ACL 和权限系统；
- 完整工作流或任务平台。

若方案需要自行建设上述主体能力，应重新分类为 C；若其规模或长期责任不可控，应分类为 D。

## 递归评估流程

1. 将目标拆成可独立验收的需求，标明关键能力、优先级和非目标。
2. 固定每个候选的版本，从一手资料拆解可独立复用的单位能力。
3. 建立 `R × O` 证据矩阵，区分原生支持、适配后支持、未知和不支持。
4. 对拟采用的能力组合验证语义、接口、数据、生命周期、许可和运维兼容性，形成 `C`。
5. 计算 `G`，列出 `E`，并估算初始成本与持续成本。
6. 用最小 PoC 验证关键未知项和最昂贵的适配假设。
7. 判定 A、B、C 或 D；若为 D，引入新候选后从第 2 步再次执行。

## 搜索与停止规则

出现以下任一情况时，应尽早转向 D，避免在错误基座上继续投入：

- 候选缺失一项不可外置的关键能力；
- 多个组件组合后仍无法满足目标语义；
- 适配层开始拥有主体数据模型或主体业务状态；
- 组合、升级或运维成本随组件数量非线性增长；
- PoC 证明关键假设不成立；
- 许可、安全或数据治理要求不可接受。

满足以下条件时可以停止搜索并进入实施：

- 所有关键需求都有固定版本的一手证据或 PoC 证据；
- 未知项均已消除，或有明确且可接受的验证计划；
- `G`、`E`、风险和退出路径已明确；
- 决策分类及其判定标准一致；
- 已定义实施阶段的验收指标和止损条件。

## 决策记录要求

每次应用本模型，应留下最小决策记录：

- 目标需求与关键能力；
- 候选项目及固定版本；
- `R × O` 证据矩阵；
- 选定组合 `C` 与能力缺口 `G`；
- 自有责任 `E` 及成本估计；
- PoC 结论；
- A、B1、B2、B3、C 或 D 的最终分类；
- 采用理由、主要风险、退出路径和重新评估触发条件。

**完成标准**：第三方 Agent 仅凭该决策记录，即可复核分类依据，并能识别哪些结论来自证据、哪些仍是假设。
