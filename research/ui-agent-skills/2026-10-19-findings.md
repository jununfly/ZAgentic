## 结论链

### C01 — A2UI 的强项是受 catalog 约束的声明式协议，不是视觉设计

A2UI 的 canonical evidence 将其描述为 platform-agnostic、streaming-first 的 UI protocol；catalog README 进一步说明 catalog 声明 Agent 可引用的 components/functions，Dart core 负责协议 envelopes、catalog schemas、function evaluation 和 reactive surfaces。它适合承接动态 UI 的 transport/render seam，但不能替代产品风格、信息架构和本地设计系统。证据：`e81904980ddf4b1d27b97743`、`f6953a4127c68a86005995ed`、`bdbee860fef6348d41daea8e`（见 ledger；正式 IR 使用精确 ID）。

### C02 — Claude Code frontend-design 提供可直接抽取的视觉方向 skill 形态

固定 commit 的 `plugins/frontend-design/README.md` 明确强调 bold aesthetic choices、distinctive typography/color palettes、animations 和 context-aware implementation；同仓库的 plugin-dev 资料也展示了 skill/agent/command 的组合与验证入口。它适合作为设计方向方法和 skill packaging 参考，不应作为 ZAgentic 的阶段编排或 artifact SSOT。证据：`3ae62d14a0a10b188170186b`、`8a8f0deb234e876e80069c7a`、`8c3077504ffae0bd1d791c76`、`5dbf30c47a4ed0236c75134b`。

### C03 — Taste Skill 把 anti-slop 视觉工作流做成了可执行的 skill

Taste 的固定版本说明其 art direction 来自 247 个 curated sites，并通过 inventory、方向选择、浏览器 inspect 和截图复审约束 Agent；canonical excerpt 明确指出 `inspect.mjs` 会在 1440/768/390 运行，并检查标题、规则、渐变、阴影等 house rules，同时记录图片 credits。它是最适合吸收进 `zj-ui-direction` 与 `zj-ui-visual-review` 的方法来源之一，但 Node 22/浏览器/外部素材是持续维护责任。证据：`5756cd53618056f488895a9a`、`d20c1cf467a0817df8a2160e`、`51da5eb7b81e0bd894f7dc58`、`aeb41de7a8ff06ba9faa2fed`。

### C04 — json-render 给生成式 UI 提供了 catalog/MCP/renderer 的工程 seam

其 MCP example 说明会注册 `render-ui` tool，并以 catalog prompt 约束模型生成 json-render spec；同一 example 将 React app 打包为自包含 HTML，使用 `useJsonRenderApp`，并把 MCP client、catalog、spec 和 renderer 连接起来。它适合作为 React/Next.js 垂直切片的 B1 adapter，但引入 runtime/package/version 组合成本，不能成为所有项目的默认前端架构。证据：`102a08a78a10e54c903ea9a8`、`039a71f2bb48723561081395`、`68c3f85dff59434e0066931a`、`f1866754163fa26a5926fa96`、`193ed3f0de7799b718a7efab`。

## 组合含义

这些候选按角色分为四组：

1. **设计判断**：Claude frontend-design、Taste、Oil UI、UUPM、Superdesign；Emil 提供动效/原型/破坏性审查。
2. **声明式动态 UI**：A2UI 和 json-render；M3E 是设计输入 document，不是同一层的 runtime。
3. **工程验证**：Storybook；Figma 是外部设计上下文入口。
4. **ZAgentic 自有缺口**：全生命周期编排、统一本地 artifact、跨 adapter 转换、权限/审批、退出路径、验证 receipt 和交接。

因此建议自有 `ui-brief/v1`、`UI-DESIGN.md`、`ui-flow/v1` 和 verification receipt，外部只通过薄 adapter/plugin 接入。v2 ledger 的 `unknownCriteria` 仍需在 Emil feedback 回写、json-render design-direction、Oil/Superdesign agent composition 等处补 PoC，不应将未知解释成不支持。
