## 仓库主要方法论与使用方式

### 方法论

1. **默认路由到 poteto-mode。** `poteto-mode` 把复杂度、架构选择、未知原因 bug、性能问题、并行扇出、争议设计、提交前清理、评审前清理、运行中验证、长期自治等触发条件编码成路由规则；同一文件还列出 24 个不可调用的原则技能。[poteto-mode](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L14-L39) [poteto-mode principles](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L41-L82)
2. **先认知，再设计，再实施，再验证。** `how` 解释运行方式，`why` 调查动机和决策，`architect` 先写类型/签名/模块草图，`arena` 做平行候选和交叉评审，`interrogate` 做对抗审查，`poteto-mode` 的 playbooks 负责 bug/feature/PR/发布等端到端流程。[architect](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/architect/SKILL.md#L12-L22) [how](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/how/SKILL.md#L12-L59) [why](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/why/SKILL.md#L12-L17)
3. **以可复核证据收尾。** `prove-it-works` 要求检查真实产物；`benchmark-checklist` 要求确认 limiter、调参、错误、重复性、端到端相关性和工作确实发生；`show-me-your-work` 用追加式 TSV 保存决策、原因、证据和结果。[prove-it-works](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/principle-prove-it-works/SKILL.md#L7-L25) [benchmark-checklist](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/benchmark-checklist/SKILL.md#L12-L33) [show-me-your-work](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/show-me-your-work/SKILL.md#L10-L24)
4. **把重复经验编码为结构。** `correct` 要求从架构、类型、lint/CI、测试到文档逐层固化重复错误；`principle-encode-lessons-in-structure` 明确优先选择不可表示状态、lint、canonical helper、运行时检查等机制。[correct](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/correct/SKILL.md#L12-L29) [encode-lessons](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/principle-encode-lessons-in-structure/SKILL.md#L7-L26)
5. **自治但保留不可逆操作闸门。** `poteto-mode` 允许可逆工作直接推进，把 force-push、生产数据删除、外发消息等列为需要暂停的不可逆操作。[poteto-mode autonomy](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L84-L92)
6. **运行时适配而不是假设跨平台一致。** 同一技能树服务 Claude Code、Codex、Pi、GitHub Copilot 等，但要求读取各运行时 mapping；自动路由由 Claude/Codex/Copilot hooks 或 Pi extension 注入。[poteto-mode platform adaptation](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L8-L12) [runtime support](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/docs/reference.md#L48-L76)

### 使用方式与依赖

- Claude Code：`/plugin marketplace add michael-denyer/pstack-claude`，再 `/plugin install pstack@pstack-claude`；Codex 和 Copilot 有各自 marketplace/add 命令，Pi 用 `pi install git:github.com/michael-denyer/pstack-claude`。首次任务可直接对 `poteto-mode` 描述目标，或显式调用 `/pstack:<name>`。[README install](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/README.md#L18-L52)
- skills-only 安装：clone 后把 `plugins/pstack/skills/*/` 链接到 `~/.agents/skills/`，或者通过 `npx skills add ... --skill "*" --agent "*" --yes` 复制技能；链接安装要求保留 clone 路径用于更新。[reference shared installation](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/docs/reference.md#L78-L108)
- 配置依赖：`setup-pstack` 选择角色模型并写 override sheet；PR 监控和 shipping 需要 `gh`；bundled `watch-pr` 和 `orch` 需要 Bun；Orchestrate 可能需要 Graphite `gt`；`automate-me`、`reflect`、`poteto-mode` 的技能编写工作需要 `plugin-dev`。[reference dependencies](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/docs/reference.md#L164-L190)
- 运行时核心耦合：skills 本身大量使用 Claude Code 的 `Skill`、`Agent`、`AskUserQuestion`、`TaskCreate/TaskUpdate`、`loop`、`run`、`verify`、`gh` 等语义；`poteto-mode` 明确要求其他运行时读取 mapping，而不是假设工具名可直接复用。[poteto-mode adaptation](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L8-L12) [reference dependencies](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/docs/reference.md#L164-L190)

## 逐个 skill 证据与 merge 输入

下面每行都对应固定 commit 的一份 `SKILL.md`。`输入/输出` 是该 skill 明确要求或自然推导出的 agent contract；“初步 merge 观察”只描述可复用边界，不替代下游 capability-fit 的 A/B/C/D 判定。

## 主要优点、主要限制与合并风险

### 优点

- 能把“一个任务”拆成 router、调查、设计、并行候选、对抗评审、验证、写作和复盘等可组合单元；这是其最适合本仓库“快速组装能力组合”目标的部分。[reference command map](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/docs/reference.md#L5-L46)
- 把证据和 verification 当作输出契约，要求保存 decision trail、真实运行证据和不确定性，而不是只返回 prose。[show-me-your-work](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/show-me-your-work/SKILL.md#L35-L75) [create-verification](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/create-verification-skill/SKILL.md#L26-L45)
- 原则技能多数是小而明确的 decision rules，适合被现有更大技能吸收，不必重复维护完整工作流。[principle tree](https://github.com/michael-denyer/pstack-claude/tree/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills)
- 运行时代码有 tests、deadline、schema parsing、worktree/merge safety 等实现质量，适合单独做 capability fit，而不是把整个 plugin 当成一个不可拆整体。[poteto scripts](https://github.com/michael-denyer/pstack-claude/tree/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/scripts)

### 限制和风险

- **Claude/runtime 耦合高。** 技能正文默认 Claude tool names、model names、transcript locations、task tracking、loop/run/verify；虽然提供 Codex/Pi/Copilot mapping，但这些 mapping 本身也是要维护的适配层。[poteto-mode adaptation](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L8-L12)
- **组合入口的政策侵入性高。** `poteto-mode` 不只是一个可移植 workflow，还规定回复格式、子 agent 模型选择、自动 routing、todo/decision trail 和暂停边界；直接复制会与本仓库现有 AGENTS、skills、roadmap、research 和 docs governance 规则冲突。[poteto-mode](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L14-L39) [autonomy](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/poteto-mode/SKILL.md#L84-L104)
- **外部服务和写操作责任明显。** PR skills 会读取 GitHub 状态、提交、push、改变 merge/queue；`watch-pr`/shipping scripts 还涉及自动 merge cancellation/landing，需本仓库独立审批、Git wrapper、退出路径和版本固定。[babysit](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/babysit/SKILL.md#L22-L54) [reference dependencies](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/docs/reference.md#L170-L177)
- **来源混合。** 大多数 pstack 内容来自 Cursor，7 个 cursor-team-kit skill 另有许可来源，`babysit` 独立 authored，端口还有本地改写；若 merge 必须精确保留 NOTICE/LICENSE 和改写边界。[NOTICE](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/NOTICE.md#L7-L18)
- **证据门槛不完全机械。** `how`/`why`/reviewer 等很多输出靠 agent 遵守 prose contract，没有统一 JSON/schema gate；只有部分 scripts/tests 提供机械验证。这意味着 merge 后要把可复用的判断协议接入本仓库的 roadmap/evidence/quality gates。[why output contract](https://github.com/michael-denyer/pstack-claude/blob/3b0bc62e13f507c426997ba472e3430dd3e4ef05/plugins/pstack/skills/why/SKILL.md#L126-L163) [scripts/tests](https://github.com/michael-denyer/pstack-claude/tree/3b0bc62e13f507c426997ba472e3430dd3e4ef05/tests)

## 后续 capability-fit 应使用的候选拆分

为避免把整个 pstack 当成一个候选，后续 R×O 至少拆成以下候选单元并固定同一 commit：

1. `O-router`: `poteto-mode` 的任务分类、原则触发和组合路由。
2. `O-research`: `how`、`why`、`teach` 的调查/解释协议与 references。
3. `O-design-review`: `architect`、`arena`、`interrogate`、`blast-radius`。
4. `O-verification`: `create-verification-skill`、`maintain-verification-skill`、`benchmark-checklist`、`prove-it-works`、`show-me-your-work`。
5. `O-principles`: 24 个隐藏原则，按领域与本仓库现有技能做去重合并。
6. `O-pr-maintenance`: `babysit`、`fix-ci`、`fix-merge-conflicts`、`get-pr-comments`、`make-pr-easy-to-review`、`watch-pr`/`shipping` scripts。
7. `O-writing`: `unslop`、`technical-writing`、`bro`。
8. `O-personalization`: `automate-me`、`recall`、`reflect`、`setup-pstack`、`poteto-help`。
9. `O-language`: `typescript-best-practices`。
10. `O-cursor-team-kit`: `deslop`、`thermo-nuclear-code-quality-review` 及其 provenance/license 单元。

这个拆分能把 native/ adapted/ unknown/ unsupported 证据和适配成本分开，避免因为整个 plugin 的 runtime glue、PR 写操作或 license bundle 而错误地否定其中的可移植方法论。

## 未知与证据边界

- 本 findings 只固定并读取上游仓库文件；没有在本地实际安装 Claude Code、Codex、Pi 或 Copilot，也没有运行需要外部账号/网络写权限的 PR shipping/live smoke tests。README/reference 中的“tested”是上游作者的记录，不能当作本次运行验证。

- 没有把 Stars、README 长度或 feature 数量当作 capability score；仓库的 GitHub metadata、实时 issue/PR 讨论和运行时账号状态未作为本 findings 的能力证据。
