# R1 闸门阈值 N 校准 PoC —— 探针原始产出与标注

> 被测原文：`docs/agreements/open-source-capability-fit-decision-model.md`（133 行）。
> 被测角色：base {B, C, A}。每个角色按 gated method 牙齿产出，分别尝试满足 N=2/3/4/5。
> 标注：**[真有效]** = 结构错位 + 引用原文证据 + 非回声；**[注水:子类]** = 复述/空泛/回声/无证据/硬凑；**[回声X]** = 与另一角色观点重复。
> 自指偏差声明：本 Agent 同会话产出，作者即评审；结论为初值建议，待 Human 跨会话复核。

## B（技术经理）视角

**观点 1 [真有效]** — 递归流程第 6 步「用最小 PoC 验证关键未知项」（原文 L96）
- 发现：流程要求每次递归都跑最小 PoC，但「最小」无验收口径与代价上限。
- 影响：候选多、递归深时 PoC 成本非线性累积，可能越过 D 红线（L106「组合成本非线性增长」）却仍被忽略。
- 建议：给 PoC 设显式代价上限（如 ≤0.5 人日）+ 跳过条件（同类未知已有 PoC 则复用）。

**观点 2 [真有效]** — 决策记录要求（原文 L118-131）
- 发现：要求 8 项最小记录，但未定义「谁维护、何时归档、绑定哪个 commit/PR」。
- 影响：快节奏采用中记录易成摆设（写了不复核），违反 L131「第三方 Agent 可复核」。
- 建议：决策记录须绑定 commit/PR 引用 + 复核人字段，否则视为未留痕。

**观点 3 [真有效]** — 可控 B 边界（原文 L70-87）
- 发现：「可控 B」靠「可承担 / 不应重复建设」清单界定，但「规模或长期责任不可控」无量化阈值（L87）。
- 影响：边界判定主观，易静默滑向 C（自有架构成主体）而无人察觉。
- 建议：给「不可控」加可量化信号（适配层 LOC > 主体 20%、或持有主体状态），触发自动重分类。

**观点 4 [真有效]** — 默认优先顺序（原文 L62-68）
- 发现：顺序非强制，但「选靠后方案须记录理由」中「足以抵消」无触发阈值（L68）。
- 影响：落地时「记录理由」易无据可查，失去约束意义。
- 建议：选非默认顺序须附量化权衡（成本差 vs 差异化价值）。

**观点 5 [borderline 注水]** — 停止规则（原文 L110-116）
- 发现：停止条件要求「已定义实施阶段验收指标」，但模型不提供模板。
- 影响：验收指标定义成本被低估。
- 建议：附验收指标模板。
- 标注：与观点 1（PoC 主题）相邻，建议弱、信息增量低 → 逼近注水。

**B 小结**：真实有效约 **4 条**；N=2/3/4 全真有效，N=5 边际 borderline 注水。工程视角饱满，N=3 稳。

## C（产品专家）视角 —— solo 内部方法论文档（市场原义空转）

**观点 1 [真有效]** — 目标与适用范围（原文 L9-13）
- 发现：模型面向「评估是否采用外部开源项目」，但本仓库 zj-discuss 是**内部自用方法论**，无真实外部市场。
- 影响：C 的「用户价值 / 生态·竞品」锚点在内部工具上几乎空转（role-matrix L37-38 已自承）。
- 建议：solo 场景 C 应改写为「对自身工作流的增效证明」（自证价值），否则视角空洞。

**观点 2 [真有效]** — 完成标准（原文 L131）
- 发现：「第三方 Agent 仅凭记录即可复核」——但本场景下「用户」规模=1（未来 zj 自己或另一 Agent）。
- 影响：价值主张弱，可证伪性落空。
- 建议：把「第三方 Agent 复核」具体化为「同仓库未参与决策的 Agent」，否则可证伪性空转。

**观点 3 [borderline 注水]** — 默认优先顺序差异化价值（原文 L62-68）
- 发现：允许为「差异化价值」选靠后方案，但没说差异化价值对谁而言。
- 影响：solo 场景无用户反馈闭环，差异化价值易成自嗨。
- 建议：差异化价值须有外部可观察信号，否则降级为内部一致性约束。
- 标注：与观点 1 同主题（内部场景局限），增量低 → borderline。

**观点 4 [注水:复述+无新增]** — 搜索停止规则（原文 L99-116）
- 发现：停止条件要求「关键需求有一手证据」，但内部工具「关键需求」由 zj 单方定义。
- 影响：需求真实性无外部校验。
- 建议：（强行凑第 4 条，无实质新增，复述观点 1/2 的「无外部校验」母题）
- 标注：硬凑，无独立信息 → 明确注水。

**观点 5 [注水:复述]** — 同上延伸，纯复述，省略。

**C 小结**：真实有效约 **2 条**；N=2 全真，N=3 第 3 条 borderline，N=4/5 明确注水萎缩。**R1 风险集中于 C**——solo/内部场景 N=3 已偏严。

## A（架构师）视角

**观点 1 [真有效]** — 可控 B 边界（原文 L70-87, L77, L105）
- 发现：「claim/lease 等小型协调语义」可承担（L77），但 L105 把「适配层拥有主体状态」列为转 D 信号。
- 影响：claim/lease 恰是 外部适配层 在 zj-discuss 实际承担（design.md §8）——边界模糊时易逐步吞掉主体状态。
- 建议：列「可承担协调语义」的明确枚举上限，防适配层渐进越界。

**观点 2 [真有效]** — 默认优先顺序 override（原文 L68）
- 发现：override 靠「记录理由」维系长期一致性，无结构化校验。
- 影响：演进中易丢失被放弃默认方案的约束记忆。
- 建议：override 须记录「被放弃默认方案的不可接受点」。

**观点 3 [真有效]** — 递归评估流程证据矩阵（原文 L89-97, L93）
- 发现：R×O 证据矩阵随候选新增重算，无版本锚定。
- 影响：多次递归后矩阵漂移，前后决策不可比。
- 建议：每次递归锁定候选版本快照，矩阵引用快照 hash。

**观点 4 [真有效]** — 决策分类定性阈值（原文 L47-54）
- 发现：「G 和 E 均可忽略」「缺口小且可控」等定性词无量化。
- 影响：同一项目不同人判 A 还是 C 可能不一，跨次决策不可比。
- 建议：给「可忽略 / 可控」附相对阈值（如 E < 初始开发 10%）。

**观点 5 [回声C / 注水]** — 完成标准（原文 L131）
- 发现：与 **C 观点 2** 撞车（同指「第三方 Agent 复核」的可证伪性）。
- 影响：A 与 C 在此点回声，独立性失效。
- 标注：重复 C 观点 2 → 注水（角色独立性破坏）。

**A 小结**：真实有效约 **4 条**；N=2/3/4 全真，N=5 回声 C（注水）。约束视角饱满，N=3 稳。
