# UI-DESIGN direction cards — R3/h8

三张候选卡；本阶段 human_gate = required，必须由人签一个方向后才进 design-system。

## card-a · "Quiet Ledger"（安静台账）
- 色彩：中性灰阶 + 单一强调蓝；语义色只有绿（成功）/ 琥珀（警告）/ 红（失败）。
- 字体：系统 sans 栈，1 个字族，靠字号与字重分级。
- 密度：紧凑，表单单行 40px，信息密度偏向"一次看完全部字段"。
- 动效：无位移缓动，只有状态色变化（<=120ms）。
- 适用场景：审批这种需要横向比对多条记录的表面。
- 取舍：省空间，但失败/警告的视觉冲击弱，容易看漏 timeout 标记。
- 参考来源：自有；license：本仓库。

## card-b · "Explicit Gate"（显式闸门）
- 色彩：同上强调色 + **失败/未确认状态使用描边 + 图标 + 文案三重冗余**，不靠单一颜色。
- 字体：数字与金额用等宽，字段标签 12px 全大写字间距拉开。
- 密度：宽松，每个表单项下方预留 1 行错误位，避免校验出错时布局跳动。
- 动效：提交中给确定性进度（按钮 disabled + spinner），不做乐观更新。
- 适用场景：强校验、强确认、强失败反馈的两条流。
- 取舍：占屏更多；换来的是" blocked / locked / timeout / denied "四种状态都能被肉眼区分。
- 参考来源：自有；license：本仓库。

## card-c · "Single Rail"（单轨向导）
- 色彩：分区标题用重色块，表单区浅底。
- 字体：标题 serif，正文 sans。
- 密度：极低，一屏一步（先填 → 再确认 → 再看结果）。
- 动效：步骤位移滑动。
- 适用场景：引导型低熟练度用户。
- 取舍：阻断型反馈很重，但审批人需要一次看到金额/事由/附件/历史版本，向导会把信息切碎。
- 参考来源：自有；license：本仓库。

## 决策（human gate）
选定 **card-b**。理由：两条流的核心风险不是好不好看，而是"用户误以为保存成功了"和"越权被静默放行"。
card-b 的冗余状态表达直接对应这两条；card-c 与 y 的同时可见性冲突，card-a 的弱失败反馈会削弱
honest failure 这条硬要求。签名者：operator-r3-h8（本 lane 唯一操作人）。

不采用：「默认取第一张卡」是被禁止的，因此 card-a 虽排在首位也不自动生效。
