# UI-DIRECTION · 方向候选与 Human 选定

S3 DIRECTION 产物。Human 选定：card-b（审计可读的中性密度）。

## 候选卡

### card-a · 高信息密度控制台
- 色彩：深底 + 高饱和青色强调
- 字体：紧凑 monospace 主导
- 密度：一屏塞下全部字段与日志
- 动效：快速平移切换
- 适用：内部运维台
- 取舍：信息密度高，但失败反馈容易被淹没，不利于"失败不能被误读为成功"的要求
- 参考来源：仓库自有past design tokens（source: internal / license: repo-owned）

### card-b · 中性密度、状态可读优先（选定）
- 色彩：浅底 + 深灰文本 + 单一语义红/绿错位反馈，不使用颜色作为唯一区分
- 字体：系统 sans-serif 栈，无外部字体（license clean）
- 密度：每个表单一屏内，状态条与 Human gate 记录常驻可见
- 动效：尊重 reduced-motion，无自动播放动画；状态变化用文本+图标同步表达
- 适用：需要把 human gate / 422 / 超时显式暴露给用户的表单与审批
- 取舍：屏幕利用率低于 card-a，换来状态与失败原因的可读性
- 参考来源：仓库自有 UI 约定（source: internal / license: repo-owned）

### card-c · 极简单列
- 色彩：近黑白，无强调色
- 字体：大字号 serif
- 密度：一次只呈现一个问题
- 动效：淡入
- 适用：向导式单任务
- 取舍：审批这种需要同时看「申请人 + 审批人 + 系统」三方动作的页面会被拆散

## 选定理由
card-c 无法承载双角色并排操作，card-a 会弱化失败反馈；card-b 满足"错误必须显式、审批不伪造成功"的产品约束。

## 未自动替换说明
方向不唯一，未在系统内自动挑选；本文记录 Human 选定方向为 card-b，作为 UI-DESIGN 的唯一输入。
