# 用户需求（裸需求，两条 lane 逐字节相同）—— R1 契约层

我要做两个页面（同一个产品里），数据都用本地 mock，不要真后端：

## 页面一：用户资料编辑表单
- 加载并展示当前资料（昵称 / 邮箱 / 简介）
- 三个字段都能编辑，输入时实时校验：昵称必填、邮箱格式、简介长度上限
- 校验不通过不能提交；提交中锁定输入（连续点两次只能生效一次）
- 提交成功和失败都要有明确反馈；失败后用户能改完再提交（可恢复）
- 提交必须由用户显式确认，不能自动提交
- 服务端可能返回 422 或直接超时；超时不能让用户以为保存成功了

## 页面二：费用报销审批
- 申请人填报销单：金额、事由、附件（附件用 mock 引用即可）
- 金额必须 > 0，事由必填
- 提交后进入审批中，审批人查看后通过或驳回（驳回必须写理由）
- 驳回后申请人能改完重新提交，形成新的一版
- 审批动作只能由审批人角色发起；其他人调用必须被拒绝，且状态不能前进
- 每次提交、每次审批决定都要用户/审批人显式确认
