# UI-BRIEF — 资料编辑 + 费用报销审批

- artifact_kind: UI-BRIEF.md
- revision: 1（source: raw-requirement.md 逐字输入）
- 产出方: S1 INTAKE

## goal
在同一个产品内提供两个可独立打开、全部本地 mock 的页面：用户资料编辑表单、费用报销审批流。
两页都必须让"提交/审批"这一步由人显式确认，并在客户端校验、并发点击、服务端 422 与超时下
给出不误导的反馈。

## goal_users
- 普通用户（编辑自己的昵称/邮箱/简介）
- 报销申请人（填写金额、事由、附件引用并提交）
- 审批人（under_review 队列中通过或驳回，驳回必须写理由）

## tasks
1. 加载并回显当前资料；三字段可编辑，输入即校验；校验不通过不可提交。
2. 提交中锁定输入，重复点击只生效一次；成功/失败均有明确反馈，失败后可改再提交。
3. 申请人填单（金额、事由、附件 mock 引用），金额 > 0、事由必填。
4. 提交 → submitted → under_review；审批人通过或驳回（驳回必填理由）。
5. 驳回后申请人改完重新提交，形成新版本，旧版本记录保留。
6. 非审批人角色发起审批必须拒绝，且状态不前进。

## constraints
- 零依赖 ESM + 静态 HTML，无后端；持久化只用 localStorage 的 mock 存储。
- 状态机、校验、写盘全部在 .mjs 模块内，HTML 只做绑定与呈现。
- 服务端 422 与超时必须可表达，且绝不返回成功态。
- 每次提交/审批动作需要显式确认（human gate），禁止自动提交。

## success_criteria
- 12 条冻结 fixture（F-1..F-6 / A-1..A-6）全部 match，driver 退出码 0。
- 超时路径落到稳定路径并显式标记"结果未知"，不伪造成功。
- 审批被拒时既有 revision 保留，新版本号递增。
