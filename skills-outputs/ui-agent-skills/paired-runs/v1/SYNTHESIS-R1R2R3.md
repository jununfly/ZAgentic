## 4. 可以说的结论（有限定词）

> 在 **AI-operator、契约层、n=2** 条件下，`skills-path` 相比 `direct-prompt`：
> **逃逸缺陷的严重程度约低 40–55%**，代价是**返工约多 7 倍、耗时约多 8.5 倍**。

限定词一个都不能少：

- **AI-operator**：DEV-2——决策时间是 operator 完成时延，不是人类决策时间；
- **契约层**：渲染层/键盘可达性未实测（BLK-3，无浏览器）；
- **n=2**：三次 run 的要求尚未满足，缺 R4；
- **direct-prompt 的对照组是"同一模型不接技能链"**，不是"人类工程师"。

## 6. 给技能链本身的反馈（与毕业无关，但最有价值）

三轮跑下来，fixture 全绿（12/12 × 6 lane）**从未阻止**以下缺陷出现：

1. **状态迁移在 UI 上不可达**（R1 h4）——fixture 用 `initial_state` 直接注入，永远测不到这段；
2. **静默数据丢失 / 伪成功**（R3 h7、h8 两条 lane 都出现）——需求明写"不能让用户以为保存成功"，但没有对应门禁；
3. **非法迁移返回值被吞**（R2 h5 critical：idle→submitting 非法却照常 `locked=true`）——状态机的返回值没人检查。

这三条的共同点：**都是"契约层测不到、用户层才暴露"**。建议给 `zj-ui-verify` 补三类机械门禁：迁移可达性（已有 v4 实现）、失败不得渲染为成功、状态机返回值必须被检查。这比毕业结论本身更值钱。
