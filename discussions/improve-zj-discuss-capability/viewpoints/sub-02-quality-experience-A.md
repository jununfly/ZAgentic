**观点 1** — Q1 bug1 的真正根因不在"缺强制"，而在「准备阶段清单」与 SSOT 是两条数据通路，修复须消除这条分叉
- 发现：原文把根因写作"该步靠 AI 自觉，无强制"（原文 L17），并承认 launch_pack 启动包已带 intro（原文 L17 末句）。但 role-matrix.md 早在 L69-73 就规定准备阶段"每个角色带一句话简介 + 推荐理由"——约束已写进规范，只是没落到可执行层。关键缺口是：启动包走 `launch_pack.py` 的 `load_role_pool`（launch_pack.py L54-81，L94 渲染 `{{intro}}`），而准备阶段推荐清单是 lead AI 的自由文本，二者没有共享对 role-matrix 的读取。两条通路 = 同一份简介可能漂移成两份真相。
- 影响：若只加一句"请 AI 务必带简介"的提示词，等于在分叉的第二条通路上再贴一层自觉，根因未除、必复发。更隐蔽的耦合风险：check_subdoc 四不变式（SKILL L196-210）只校验"视角块内容 + 来源标注"，完全不校验"准备阶段推荐了哪些角色、是否带简介"（原文 L16 的可选 key 与结论覆盖是独立逻辑），所以漏带简介不会触发任何闸门——错误对质量护栏隐形。量化：当前准备阶段简介强制率 0%（纯 prose），且护栏对该失效 0% 可见。
- 建议：把准备阶段角色清单渲染与 `launch_pack.py` 的 `load_role_pool` 合并为单一读取 role-matrix 的入口，准备阶段输出强制为 `key / 一句话简介 / 推荐理由` 三段（理由来自 base 或命中信号，复用 role-matrix L54-67 的映射）；新增回归测试断言 role-matrix 每个 key 的 intro 单元格非空（空则报错而非静默）。自定义角色（`--allow-custom`，launch_pack.py L191-169 拒绝逻辑）intro 为空时显式标注"（自定义角色，无矩阵简介）"而非崩溃。验收：准备阶段与启动包产出同源、无简介缺失；护栏对"声明集与简介完整性"有机器校验兜底。

**观点 2** — Q2 引用不变式与证据闸门各有一处可被拆行/换写法绕过的泄漏，冲击硬规则 3(b) 权威红线
- 发现：check_subdoc.py 对"结论不得引用同会话预演为权威"的判定是"同一行内同时出现 PREVIEW_TOKEN 与 RELIANCE_CUE"（check_subdoc.py L123-133；SKILL L202-205 同述）。这是单行启发式而非结构化解析。证据闸门 `EVIDENCE_RE = 原文\s*[L（(]`（check_subdoc.py L67）只认 `原文 L/（/(`，写成"见 role-matrix 第 96 行"或"依据上述同会话产出"跨行拆开即漏判或误杀。另：gate 只数带证据块数，并不校验观点是否真回答了 Q1/Q2/Q3——而 sub-02 明确要求"回答 Q1/Q2/…"（原文 L33），此实质不变式无机器校验。
- 影响：① 引用红线有假阴性（拆行即可静默绕过），权威依据判据形同虚设；② 证据格式过窄造成假阳性，逼 Agent 套"原文 Lxx"模板，长期诱发"为过闸注水"；③ "答了开放问题"不在闸门内 → "闸门通过 ≠ 问题已解"的语义漂移，与四不变式想兜住的"结论可信"目标相悖。量化：引用判定对多行写法的覆盖率 <100%，证据正则字符集仅 3 个开头。
- 建议：① 引用校验改为按 `## conclusion` 块（section）作用域扫描，而非单行（check_subdoc.py L110 `_check_conclusion` 已按 body 遍历，只需把"同行"改为"同 body 任意行同现"）；② 证据正则放宽到 `(原文|见原文|原文第)\s*[^\s，。]+` 并在各 role-methods 明确规范范式，避免 Agent 猜格式；③ 新增 warning 级"开放问题覆盖"软校验：视角块正文至少各出现一次 `Q1`/`Q2`/`Q3` 锚点，把"答了问题"纳入可观测。验收：拆行引用被捕获、章节锚点证据放行、缺 Q 锚点给 warning 不阻断。

**观点 3** — Q2 `--all` 链路自洽，但"非降级锚点"信任基底是 Agent 自证，不是隔离验证，须显式记为边界
- 发现：SKILL L105-111 已正式关闭 `--role X,Y`、把 `--all` 定为唯一合规替代（输出独立启动行），launch_pack.py L31 用 `声明必需角色集` 正则解析本子文档 L12 的 `B,C,A,O`，链路自洽无 usability 缺口。但 check_subdoc 的"非降级锚点"（check_subdoc.py L228-248）只认 `视角来源:` 字面声明，无法验证该视角是否真跨会话——同会话预演若误标 `跨会话独立Agent` 即可骗过锚点判据。
- 影响：收敛判据（声明集全覆盖）的信任基底是"Agent 自报来源"，不是可验证隔离。跨 provider 不可强制（硬规则 6，SKILL L246-254 仅"推荐"），故可接受，但它属于结构性信任边界而非已验证不变式。若被误读为"机器已确认隔离"，会在高利害子问题（易回声室）上给假安全感——而 role-matrix L83 恰恰说这类子问题该用跨会话独立 Agent。
- 建议：在 SKILL 硬规则 6 附近补一句"来源标记为自证式断言，非运行时验证"的边界说明；并在 `## Human 拍板` 表（原文 L70-77）增加一列"隔离方式（跨provider / 同provider跨会话 / 同会话）"，使收敛时可见真实隔离层级，避免把同会话预演误计入有效覆盖。验收：拍板表能区分三类隔离；SKILL 明确该标记非验证。

**观点 4** — Q3 Phase 2 处置闭环的先决条件"结论须可执行沉淀"不在任何结构闸门内，是最易断的环节
- 发现：子文档 conclusion 模板要求"可执行沉淀指令：改哪些 PRD/ADR、跨子文档约束登记、待删临时脚手架"（原文 L84-89），硬规则 5（SKILL L242-244）明定"conclusion 必须含沉淀指令否则不算闭环"。但 check_subdoc 四不变式（SKILL L196-210）只校验 `状态协议` 与引用越界，完全不校验 conclusion 是否含沉淀指令/指针。sibling-boundary.md L21-24 规定 discuss 阶段 2 只吐 `<conclusion>+<suggested-category>+<pointer>`，最终分类/删除由 zj-docs-ontology 在 Human 确认闭环内完成——但本子文档结论模板没有强制挂"指向 docs-ontology 的指针"字段，briefings/（原文 L63-67 标"阶段 2 删除候选"）也无确定删除清单。

- 建议：① 扩展 check_subdoc 新增不变式 5（warning 或 violation 级）：conclusion 必须含 `沉淀指令` 段且 `待删临时脚手架` 至少列出本子文档生成的 `briefings/` 路径；② 在结论模板固定一行 `docs-ontology 指针：<调用/分类建议>`，使 discuss→docs-ontology 的交接边界可被机器核对（呼应 sibling-boundary L21-24 的"只吐指针"），而非仅 prose。验收：沉淀指令为空的 DONE 结论被闸门判 violation；补 tests 用例覆盖"空沉淀→fail"。
