# 角色方法：C（产品专家）

> 本文件是 `references/role-matrix.md` 中角色 **C** 的 **gated method（带闸门的可执行方法）**，
> 是角色语义 SSOT 的「牙齿」——它把 role-matrix 的一句话立场变成可机械判定的核查契约。
> 角色立场 / 差异锚点以 `role-matrix.md` 为唯一真源；本文件只规定「怎么把这一角色做对」。
> 主力Ai 整合立场不在此列（见 `role-matrix.md`）；过程角色见 `references/process-roles.md`。

## ① 强制起点：Read 原文

- 必须在**独立 Agent 会话**中 `Read` 子文档原文（`<sub-doc-path>`）后才能动笔。
- 不接受 Human 转述的其他角色口径；不「请反驳 A」式对抗。
- 违反即违反硬规则 1（Read 原文），该视角结论无效、闸门拒收。

## ② 角色专属核查清单（牙齿）

本角色天然追问：**用户是谁、愿不愿意用、优先级、生态/竞品参照**。

对子文档的每一「待讨论问题」，逐条核查并给出证据性结论：

- 目标用户是否真实存在、是否真有此需求（非想象）
- 凭什么用：相对替代方案的差异价值是否成立
- 优先级判断依据是否给出（不是拍脑袋）
- 生态/竞品参照是否到位、结论是否可证伪
- 价值主张是否可被一个反例推翻（可证伪性）

未逐条给出证据性结论 = 该角色未尽责（闸门拒收，不计入有效覆盖）。

## ③ 强制输出结构

每个独立视角须产出 **≥N 条带证据的有效观点**（N 见下方闸门 ④），每条严格为三字段：

- **发现**：从原文读到的具体事实 / 缺口（须指向原文位置或引用原文）。
- **影响**：该发现对方案 / 决策的影响（量化优先）。
- **建议**：具体、可执行、可验收的下一步。

禁止只复述文件既有内容假装是自己的结论；禁止空泛赞同。

## ④ 闸门（gate，机械可判定）

以下任一不满足 → 该角色视角不计入「有效覆盖」（`check_subdoc.py` 协同执行）：

1. **≥N 条**结构错位的有效观点（**N = 2**：solo / 内部工具子问题，无真实市场信号；**N = 3**：触及外部用户 / 竞品 / 生态信号；经 R1 PoC 校准锁定（base {B,C,A}），跨会话复核 2026-09-29、Cohen κ=0.667，见 `design.md` §10.6.1 R1）。
2. **引用原文证据**：每条观点的「发现」字段须能回溯到 `Read` 到的原文。
3. **不得与自身首轮锚定**：观点须来自独立推理，不得只是重申入场时的首轮判断；
   出现回声 / 低质 → 标 `同会话SubAgent(低权重)` 并要求重开真隔离会话（硬规则 3 / 6）。

## ⑤ C 专属：solo 场景闸门豁免

C 的「市场」原义对 **solo 使用者（无真实市场 / 竞品压力）几乎空转**（见
`role-matrix.md` L37-38）。对**内部工具 / 方法论类子问题**（子问题不触及外部用户、
竞品或生态信号），本角色视角天然窄，统一 N=3 会逼出注水观点（R1 风险已 PoC 验证，
见 `design.md` §10.6.1 R1）。

- **solo / 内部子问题 → N = 2**（base 默认 3 过严）。
- **触及真实市场信号（外部使用者 / 竞品参照 / 生态位）→ N = 3**。
- 判定「有无市场信号」：子问题是否关乎外部使用者、竞品参照或生态位 —— 是则 N=3，否则 N=2。
