# Role Matrix（可复用角色矩阵）

用于 `zj-discuss` 每子文档的独立多视角讨论。角色是**结构差异**，不是同一
镜头的换名——每条都带不同的「差异锚点」，确保视角真的错位而非回声。

## 两类角色

**编排者（主会话，非独立视角）：主力AI**
- 立场：产品实用主义 + 架构整合，是运行 `zj-discuss` 的**主会话编排大脑**。
- 负责：分解、合成回卷、写「主力AI 整合立场」区块。
- **不是**跨会话独立视角，明确标 `视角来源: 同会话SubAgent(低权重)`，
  **不计入**下面的独立视角覆盖。
- 措辞约定：这里的「低权重」指**非隔离、整合型**，绝不等于「弱」——主力AI 是
  编排核心，份量高；它只是不提供跨会话隔离，故其产出**永不可作为结论权威依据**。

**独立结构视角（须跨会话独立 Agent）：B / C / A**
| 角色 | 结构立场 | 差异锚点（它天然追问什么） |
| --- | --- | --- |
| **B — 技术经理** | 可落地 / 工程现实 | 排期、依赖、风险、谁来做、做到什么程度算完 |
| **C — 产品专家** | 用户价值 / 生态·竞品参照 | 用户是谁、愿不愿意用、优先级、生态/竞品参照 |
| **A — 架构师** | 约束 / 长期一致 | 边界、不变式、向后兼容、与其他系统的耦合 |

> C 的「市场」原义对 **solo 使用者（无真实市场/竞品压力）几乎空转**——故改写为
> 「用户价值 / 生态·竞品参照」，贴合 zj 的语境，避免产生空洞视角。

## 默认视角集与收敛规则（硬）

- **默认视角集 = {B, C, A}。** 收敛停规则**参数化**：当「本次子文档声明的必需视角
  集合」全部覆盖即停（默认集只是该参数的常用取值）。主力AI 是整合者，不计入覆盖。
  C 自己喊停也算数。不要「为多加视角而多加」。
- **按需增删规则（可操作化）：** 默认集不必固定第四视角。仅当某子文档**触及带验收
  标准的实现/规格**（代码、接口契约、可测行为）时，才临时挂「测试/质量」视角；
  纯讨论/设计类子文档不挂。增删走既有「声明必需集→覆盖即停」出口，不破坏不变式。
- 高利害、易回声室的子问题 → B/C/A 用**跨会话独立 Agent**（真隔离，权重高）。
- 分解 / 合成 / 核验等结构性辅助 → 可用**同会话 SubAgent**（低隔离，低权重）。

## 已验证的坑（来自真实跑通）

- **同会话角色扮演 ≠ 运行期隔离。** 同一 context window 内「扮演 B/C/A」
  权重应低于跨会话独立视角——它无法摆脱首轮锚定，易退化成回声室。
- **回声室真实存在。** 不强制结构化错位，多视角只会互相加固首轮结论。
- **结论必须给可执行沉淀指令**（改哪些 PRD/ADR、删哪个临时文档），否则
  讨论悬空、不算闭环。

## 用法

`zj-discuss` 为每子文档的**独立视角（默认集 B/C/A）**各生成一份 briefing，每份盖章
角色立场 + 强制 `Read` 原文令；Human 复制到跨会话独立 Agent 加载
`zj-discuss-view --role X <sub-doc路径>` 撰写（X ∈ 本次声明的必需集）。**主力AI 整合立场
在主会话直接写，不走 briefing。** 角色可作示例默认，亦可按子问题增删（遵循上方
「按需增删规则」），但增删后须仍满足「结构错位 + 覆盖即停」。
