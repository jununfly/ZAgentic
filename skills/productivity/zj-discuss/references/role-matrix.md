# Role Matrix（可复用角色矩阵）

用于 `zj-discuss` 每子文档的独立多视角讨论。角色是**结构差异**，不是同一
镜头的换名——每条都带不同的「差异锚点」，确保视角真的错位而非回声。

## 两类角色

**编排者（主会话，非独立视角）：主力AI**
- 立场：产品实用主义 + 架构整合，是运行 `zj-discuss` 的主会话。
- 负责：分解、合成回卷、写「主力AI 整合立场」区块。
- **不是**跨会话独立视角，明确标 `视角来源: 同会话SubAgent(低权重)`，
  **不计入**下面的独立视角覆盖。

**独立结构视角（须跨会话独立 Agent）：B / C / A**
| 角色 | 结构立场 | 差异锚点（它天然追问什么） |
| --- | --- | --- |
| **B — 技术经理** | 可落地 / 工程现实 | 排期、依赖、风险、谁来做、做到什么程度算完 |
| **C — 产品专家** | 市场 / 用户价值 | 用户是谁、愿不愿意用、优先级、商业/市场约束 |
| **A — 架构师** | 约束 / 长期一致 | 边界、不变式、向后兼容、与其他系统的耦合 |

## 收敛规则（硬）

- **覆盖 B(执行) / C(产品·市场) / A(架构) 即停。** 主力AI 是整合者，不计入覆盖。
  C 自己喊停也算数。不要「为多加视角而多加」。
- 高利害、易回声室的子问题 → B/C/A 用**跨会话独立 Agent**（真隔离，权重高）。
- 分解 / 合成 / 核验等结构性辅助 → 可用**同会话 SubAgent**（低隔离，低权重）。

## 已验证的坑（来自真实跑通）

- **同会话角色扮演 ≠ 运行期隔离。** 同一 context window 内「扮演 B/C/A」
  权重应低于跨会话独立视角——它无法摆脱首轮锚定，易退化成回声室。
- **回声室真实存在。** 不强制结构化错位，多视角只会互相加固首轮结论。
- **结论必须给可执行沉淀指令**（改哪些 PRD/ADR、删哪个临时文档），否则
  讨论悬空、不算闭环。

## 用法

`zj-discuss` 为每子文档的**独立视角（B/C/A）**各生成一份 briefing，每份盖章
角色立场 + 强制 `Read` 原文令；Human 复制到跨会话独立 Agent 加载
`zj-discuss-view --role X <sub-doc路径>` 撰写（X ∈ {B,C,A}）。**主力AI 整合立场
在主会话直接写，不走 briefing。** 角色可作示例默认，亦可按子问题增删，但增删后
须仍满足「结构错位 + 收敛即停」。
