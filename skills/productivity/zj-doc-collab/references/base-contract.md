# zj-doc-collab — 通用协作契约（base contract）

本文件定义 `zj-doc-collab` 拥有的**通用**部分：生命周期、6 条泛化硬规则、scoped-memory
模型、兄弟边界模式。不含任何消费者特有词汇（角色名、结论状态枚举、沉淀指令等）——那些是
消费者的插件点。

---

## 生命周期（P0–P4，通用形状）

- **P0 范围闸门**：单点问题不进入本方法；本方法只服务于 flat chat 无法充分收敛的复杂问题。
- **P1 解构 + 备角色**：把问题分解为 1 个主文档 + N 个子问题文档；为每个子问题从角色池
  选角色集（base 必需集 + 按信号追加的可选角色），Human 确认/锁定为 *declared required set*。
- **P2 独立讨论**：为每个声明角色生成启动包，由 Human 路由到独立会话/SubAgent；各写独立贡献；
  结构性闸门保障隔离完整性。
- **P3 合成**：增量更新主文档索引 + 终局叙事。
- **P4 处置**：分类/沉淀耐久内容，过程文档按约定删除（disposition discipline）。

固定阶段（P0–P4）不可跳过；动态议程只能在阶段内部增轮/重排，不得删减任一阶段。

---

## 6 条泛化硬规则（non-skippable）

> 这些规则对任何「多 Agent 基于文档协同」的消费者都成立；消费者可追加领域规则，不得削弱这些。

1. **Read the original.** 每个贡献必须来自一个亲自 `Read` 了共享原文的 Agent/SubAgent。
   禁止 Human 转述他人口径给第三方；禁止「请反驳 A」式对抗指令——改派结构不同的角色。

2. **Structurally different roles.** 独立贡献来自 *declared required role set* 中结构不同的角色，
   不是同一镜头的换名。编排者（主会话整合者）是低权重、非隔离，不计入独立覆盖。角色语义
   以消费者角色池（role-matrix）为唯一真源（SSOT）。

3. **Anti-echo-chamber + load-bearing warning.** 同会话角色扮演 ≠ 运行期隔离；须标为低权重，
   且其产出**永不可作为结论权威依据**——只有跨会话独立视角可信。若观察此口子系统性诱使
   Human 跳过真隔离，删除它。

4. **Convergence.** 覆盖 *declared required set*（准备阶段锁定的全部角色）即停。动态议程可
   为未解分歧插入聚焦轮，但**绝不为凑人头而加视角**。多视角是手段，不是目标。

5. **Conclusion must be executable.** 一个贡献的收敛结论必须含**可执行沉淀指令**（改哪些文档 /
   删哪个临时物）；否则不算闭环。

6. **Non-degradation ladder（非降级自检）.** 隔离阶梯：跨 provider 独立 > 同 provider 跨会话 >
   同会话 SubAgent 预演。同会话是**必经的下限，不是终点**——标为已收敛的结论必须至少有一条
   跨会话独立视角作锚点；仅有同会话预演却宣称已结论 = 静默降级，拒。

## scoped-memory 模型（通用）

- **共享上下文（shared context）= SSOT**：一套文档，承载目标定义、进度状态、共享 context。
  所有 Agent/SubAgent 从中读取一致的事实基础。
- **每 Agent scoped 私有内存**：每个参与者在共享上下文之上叠加自己的私有层（角色立场、
  私有推理、草稿），不污染共享文档；其贡献落盘时才并入共享上下文的对应区块。
- **协调原语**：目标对齐（共享目标定义 + 成功判据）、进度跟踪（共享进度状态表）、
  context 共享（文档即共享内存）。三者都通过文档结构表达，由结构性闸门保障一致性。

## 兄弟边界模式（通用）

> 全局决策 = **C（选择性复用）**：外部范式只作结构借鉴，本方法体系始终是自有主体。边界写进
> 基础而非仅 design 文档，是为防止「顺手引一个依赖」把方法所有权让渡出去。

- **引用而非重做**：消费者做薄编排层，兄弟/基础已覆盖的能力一律调用，不在消费者内重实现。
- **不变式互斥**：协作式结构错位视角与防御式辩护是不同职责，不得共享实现；辩护类子问题改调
  专门技能。
- **压缩契约**：启动包 ⊂ 通用压缩契约，仅追加消费者专属两行头。
- **治理 Human 闭环**：分类/迁移/权威校验由治理技能在其 Human 确认闭环内完成，消费者只吐指针。
- **否决项（不再复议）**：会话编排运行时 / router / suite 化 —— 会让适配层拥有主体方法状态，
  按决策模型重分类为 D。启动包生成器是这条红线的产物边界：它写文件，不发起会话。

## 参数化约定（供消费者接线）

通用脚本（`gate_core.py` / `launch_pack_core.py`）的消费者特有词汇以**参数/默认值**注入，
不写死在基础内：

- 视角来源标记、预演标记、非降级锚点标记（gate_core 默认取 zj-discuss 词汇）。
- 结论状态枚举、claimed-status 集合（gate_core 默认取 zj-discuss 词汇）。
- 每角色执行命令模板、role-method 路径、闸门脚本名（launch_pack_core 默认取 zj-discuss 词汇）。

基础的通用测试以 zj-discuss 默认词汇验证逻辑等价；消费者自带测试覆盖其特有层。
